Start Here

If you have just downloaded FORGE, do not start by guessing what every option means. Follow the sequence below once. After your first successful generation, the rest of the interface becomes much easier to understand.

Authorized use only

FORGE is intended for authorized security research, password auditing, testing, controlled experimentation, and candidate-space analysis. Only generate or test candidates where you have permission to do so.

Download → Launch → Choose Utility → Configure → Generate → Save → Resume
1

Download the public release

Get the official FORGE v1.0.0 release from the download page. The current public executable is intended for Linux x86-64 systems.

2

Launch FORGE

Open a terminal in the directory containing the executable and start the program.

3

Choose a utility

Begin with password generation if you want to construct password candidates, or use the other available utilities when your workflow requires them.

4

Define the candidate space

Provide the words, numbers, symbols, lengths, limits, and generation strategy that should control the operation.

5

Generate and save

FORGE processes the candidate space according to the selected controls and writes the resulting output according to the current workflow.

Installation

FORGE v1.0.0 currently provides a Linux x86-64 executable. Download the release and place the executable somewhere convenient.

Terminal
cd ~/Downloads


chmod +x FORGE
./FORGE

If your downloaded executable has a different filename, use that filename in the commands above.

Windows and other platforms

The current public release is Linux x86-64. Do not assume that a Linux executable can be launched directly on every other operating system. Use the release appropriate to your environment.

Your First Generation

The easiest way to understand FORGE is to run a small, controlled example first. Keep the candidate space small while learning the workflow.

Example: a small authorized test dataset

Suppose you are testing your own application and want to study how a few known terms interact with a number and symbol.

Example keywords: forge and security

Example number: 2026

Example symbol: @

Start with a deliberately small candidate limit while learning the interface.

Keywords + Numbers + Symbols + Rules → Candidates

The important lesson is that FORGE does not treat generation as one enormous uncontrolled operation. You define the inputs and constraints first, then select how the candidate space should be traversed.

Password Generation

Password generation is designed around controlled candidate construction. Your inputs become the raw material, while generation mode, length, limits, traversal and other controls determine how FORGE explores the resulting space.

MODE 01

Smart

Prioritizes structured and English-like candidate construction.

MODE 02

Scrambled

Explores rearranged candidate structures and permutations.

MODE 03

Exhaustive

Systematically explores combinations within the defined constraints.

What affects the candidate space?

Every additional input can increase the number of possible candidates. More keywords, numbers, symbols, transformations and lengths can cause the search space to grow rapidly.

Words Numbers Symbols Length Transformations → Candidate Space

Smart Mode

Smart mode is intended for structured candidate generation. It attempts to prioritize combinations that resemble natural word construction rather than treating every possible ordering as equally important.

Conceptual example

Input terms: forge, security, 2026

A Smart workflow may prioritize structured candidates derived from those inputs rather than immediately exploring every possible arrangement.

The exact candidates depend on the current FORGE implementation and the options selected during generation.

When to use Smart

Use Smart when you want structured candidate exploration and want the generation process to prioritize useful word-like constructions.

Scrambled Mode

Scrambled generation is useful when the ordering of the input material matters. Instead of relying primarily on natural word construction, the workflow can explore rearranged structures.

Conceptual example

Given the input components: forge, 2026, @

the generator can explore different arrangements of those components according to the selected rules.

Scrambled mode becomes especially useful when your authorized test dataset suggests that ordering and permutation should be part of the candidate model.

Exhaustive Mode

Exhaustive generation is the broadest approach. It attempts systematic coverage of the candidate structures allowed by your selected constraints.

Control the size before starting.

Exhaustive generation can produce very large candidate spaces. Set an appropriate candidate limit and required length before launching a large operation.

Why candidate spaces grow

More input components create more possible combinations. Adding additional numbers, symbols, words, permutations or lengths can increase the workload dramatically.

More inputs → More combinations → More processing

Generation Controls

Controls determine how much work FORGE performs and what candidate structures are accepted.

Control What it controls Why it matters
Maximum candidates Limits the number of new candidates generated. Prevents an operation from expanding without a defined boundary.
Required length Restricts candidates to the requested length. Reduces irrelevant output when a specific length is required.
Generation mode Determines how candidates are constructed. Lets you choose structured, scrambled or exhaustive exploration.
Traversal Determines the order in which candidates are explored. Changes which candidates are encountered first.
Existing wordlist Provides previously generated candidates. Helps avoid repeating work in continuing workflows.

Maximum candidates

Candidate limits are one of the most important controls in FORGE. If you are experimenting with a new configuration, begin with a small limit and increase it after confirming that the workflow behaves as expected.

Example

Suppose you set the maximum candidate limit to 10,000.

FORGE can stop the generation operation when the configured limit is reached rather than continuing indefinitely.

Required length

Required length lets you focus generation on candidates of a specified size.

Example

Required length: 8

An eight-character candidate satisfies the length requirement, while candidates with different lengths do not satisfy that particular constraint.

Traversal Strategies

Traversal controls the order in which FORGE explores the candidate space.

Strategy Concept Useful when
Sequential Processes candidates in the normal generation sequence. You want predictable progression through the generated space.
Priority Gives earlier attention to higher-priority candidates. Candidate ordering matters.
Rotation Rotates traversal through candidate structures. You want a different distribution of early exploration.
Alphabetical Traverses candidates alphabetically where applicable. Ordered output is useful to your workflow.
Random Traverses candidates using randomized ordering. You want randomized exploration of the candidate space.

Existing Wordlists

A continuing generation workflow does not always need to start from an empty output file. When supported by the selected workflow, an existing wordlist can provide FORGE with previously generated candidates.

Existing wordlist → Load → Check previous candidates → Generate new candidates → Save
Why this matters

Reusing an existing wordlist can prevent unnecessary regeneration and makes long-running generation workflows more practical.

Recommended workflow

1. Keep the previous output file.
2. Load it when the workflow supports existing-wordlist input.
3. Use the same or deliberately changed generation rules.
4. Generate the next controlled batch.
5. Preserve the resulting output and state for future work.

Resume Long-Running Workflows

Some candidate-generation operations take time. FORGE can use saved state to continue a workflow rather than forcing you to rebuild the entire operation from the beginning.

Configure → Generate → Save state → Stop → Continue → Resume
Example: split a large experiment into controlled runs

Instead of attempting one enormous generation operation, divide the work into controlled batches.

Run one batch, preserve its output and state, then use the Continue workflow when you are ready to proceed.

Do not delete state files casually.

If a workflow depends on saved state, keep the relevant state and output files together until the generation process is complete.

Troubleshooting

FORGE does not start

Confirm that you downloaded the correct executable for your system and that the file has execute permission.

Check
ls -l FORGE


chmod +x FORGE
./FORGE

Generation produces too much output

Reduce the maximum candidate limit and narrow the generation constraints. Review the number of keywords, numbers, symbols, required lengths and selected generation mode.

Generation takes too long

A large candidate space can require substantial processing. Start with a small controlled experiment and increase the workload progressively.

You generated the same work again

Review whether the previous wordlist or saved state was loaded correctly. Continuing workflows depend on preserving the relevant output and state information.
